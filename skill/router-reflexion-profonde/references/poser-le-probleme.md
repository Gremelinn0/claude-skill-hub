# Méthode — Poser le problème avant de chercher une solution

Utiliser cette méthode quand le sujet est ambigu, multi-composants, ou qu'une première réponse a déjà été rejetée.

Objectif : construire une carte complète du problème avant toute recommandation.

## Sortie attendue

Produire une table qui sépare explicitement :

| Objet | Où il agit | Son rôle | Ce qu'il ne fait pas |
|---|---|---|---|

Puis ajouter :

- ce qui est déjà décidé ;
- ce qui est déjà mesuré ;
- le critère réel de décision ;
- ce qui n'est PAS le problème ;
- ce qui manque encore pour trancher.

## Les 5 questions

1. Combien d'objets distincts sont réellement en jeu ?
2. Où chacun intervient-il dans le système ou le processus ?
3. Qu'est-ce qui est déjà tranché ou mesuré ?
4. Quel est le critère réel, au-delà du proxy le plus facile à observer ?
5. Quels sujets voisins doivent être explicitement exclus ?

## Règle

Ne proposer aucune solution tant que la carte du problème reste incomplète.

Une solution construite sur une carte fausse peut être cohérente et pourtant résoudre le mauvais problème.
